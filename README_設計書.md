# 設計書一覧

## 概要

このプロジェクトの包括的な設計書セットです。各ドキュメントは異なる観点からシステムを説明しています。

---

## 📄 ドキュメント一覧

### 1. **設計書.md** - メイン設計書

**用途**: システム全体の概要と基本的なアーキテクチャ

**内容**:

- システム概要
- 技術スタック
- アーキテクチャ（レイヤー構成、パッケージ構成）
- データベース設計（ER図、テーブル詳細）
- API設計（全エンドポイント概要）
- 機能仕様（出勤・退勤、勤務表、レポート生成、セキュリティ）
- システム構成（ファイル構成）

**対象読者**: 新規開発者、アーキテクト、PM

**読むべき順番**: 最初に必ず読む

---

### 2. **技術詳細設計書.md** - 技術的詳細設計

**用途**: 実装レベルの詳細設計と技術パターン

**内容**:

- データフロー（出勤・退勤、勤務表表示、レポート生成）
- 主要ビジネスロジック（時間計算、楽観ロック、自由備考保存）
- データベーススキーマ詳細（マイグレーション戦略、インデックス）
- エラーハンドリング戦略（カスタム例外、グローバルハンドラ、HTTPステータス）
- パフォーマンス最適化（クエリ最適化、キャッシング、コネクションプーリング）
- セキュリティ実装（Spring Security、IP制限、UA フィルター、レート制限）

**対象読者**: バックエンド開発者、アーキテクト

**読むべき順番**: 設計書.md の後に読む

---

### 3. **APIリファレンス.md** - API仕様書

**用途**: 開発者向けのAPI詳細仕様

**内容**:

- 基本情報（ベースURL、認証、レスポンス形式）
- 勤務管理API（出勤、退勤、取得、更新、SSE）
- レポート生成API（Excel、PDF、ジョブステータス確認）
- 休日管理API（取得、追加）
- 認証API（ログイン、ログアウト）
- エラーコード一覧
- 使用例とシェルコマンド

**対象読者**: フロントエンド開発者、API統合担当者、テスター

**読むべき順番**: APIを使用する前に必ず読む

---

### 4. **開発ガイド.md** - 実装手引き

**用途**: 実際の開発作業のための具体的な手引き

**内容**:

- 開発環境セットアップ（Java、PostgreSQL、Maven、IDE設定）
- プロジェクト構造（ディレクトリ階層、主要ファイル）
- コーディング規約（Kotlin、Java/Spring、SQL命名規則）
- 開発ワークフロー（新機能追加の具体例）
- デバッグ方法（ログ設定、ブレークポイント、Postman）
- テストの書き方（ユニットテスト、統合テスト）
- 本番デプロイ（ビルド、環境設定、Docker、サーバーデプロイ）

**対象読者**: 実装エンジニア、QAエンジニア、DevOps

**読むべき順番**: 開発環境構築時に読む

---

## 🔍 ドキュメント利用ガイド

### ユースケース別の読み方

#### **新規プロジェクトジョイン時**

1. 設計書.md（システム全体の理解）
2. 開発ガイド.md（環境セットアップ）
3. コーディング規約セクション
4. APIリファレンス.md（利用するAPI確認）

#### **新機能開発時**

1. 設計書.md（関連機能の既存実装を理解）
2. 技術詳細設計書.md（同様のロジックパターンを確認）
3. 開発ガイド.md（新機能追加フローを参照）
4. APIリファレンス.md（新APIの仕様を確認）

#### **バグ修正時**

1. 技術詳細設計書.md（エラーハンドリング、データフロー確認）
2. APIリファレンス.md（エラーコード確認）
3. 開発ガイド.md（デバッグ方法確認）

#### **本番デプロイ時**

1. 開発ガイド.md（本番デプロイセクション）
2. 設計書.md（環境変数、設定確認）

#### **APIを利用する（フロントエンド）時**

1. APIリファレンス.md（エンドポイント、パラメータ、レスポンス）
2. 技術詳細設計書.md（データフロー理解）

## 🔧 維持管理

### 更新対象者

- **アーキテクト**: システム設計変更時
- **リードエンジニア**: 新規APIやコーディング規約追加時
- **開発者**: 技術詳細変更時

### 更新頻度

- **設計書.md**: 年2回（システム改善時）
- **技術詳細設計書.md**: 随時（技術選定変更時）
- **APIリファレンス.md**: 新API追加時（随時）
- **開発ガイド.md**: 四半期ごと（環境・ツール更新時）

### バージョン管理

全ドキュメントは Markdown 形式で Git で管理されています。

```bash
# ドキュメント更新の確認
git log --oneline -- 設計書.md 技術詳細設計書.md
```
